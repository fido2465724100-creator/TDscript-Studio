# TDscript Studio — Архитектура и дорожная карта (Core 1.1 / Studio v1.1.0)

## 1. Концепция и назначение
**TDscript Studio** — это мультиплатформенная интегрированная среда разработки (IDE) и аппаратной эмуляции для языка **TDscript Core 1.1**. Среда спроектирована для работы как на рабочих станциях инженеров (Linux, Windows), так и на мобильных устройствах прямо «в поле» (Android-планшеты и смартфоны).

Среда решает три ключевые задачи:
1. **Нативная мультиязычность (109 языков)** через двустороннюю проекцию ключевых слов без повреждения физического кода.
2. **Безопасная разработка и отладка (Zero-Risk Hardware)** через песочницу симуляции датчиков и ПЛК (`AiHardwareSandbox`).
3. **AI-First архитектура**: машиночитаемая диагностика в формате JSON с точной привязкой к строкам и физическим интерфейсам для автономных AI-агентов.

## 2. Модульная структура

```
TDscript-Studio/
├── common-editor/       # Кроссплатформенное ядро редактора и симуляции
│   ├── editor/          # Двусторонний проектор кода (CodeProjector)
│   ├── sandbox/         # Аппаратная песочница (AiHardwareSandbox: BME280, Modbus)
│   └── diagnostics/     # Генерация JSON-диагностики для AI-агентов
├── desktopApp/          # Десктопное приложение для Linux и Windows
│   └── desktop/         # Main.kt, CLI & Desktop Engine, работа с /dev/ttyUSB* и COM*
├── androidApp/          # Мобильная редакция для Android
│   └── android/         # StudioMainActivity, поддержка USB-OTG и BLE GATT
└── docs/                # Архитектурная документация и спецификации
```

## 3. Ключевые компоненты

### 3.1. `CodeProjector` (Синтаксический проектор)
* **Принцип работы**: посимвольный конечный автомат (State Machine), который распознает строковые литералы (`"..."`, `'...'`, `L"..."`), однострочные (`//`, `#`) и многострочные (`/* ... */`) комментарии.
* **Гарантия сохранности**: ключевые слова заменяются исключительно в теле инструкций и выражений, полностью исключая замену слов внутри строк и комментариев.
* **Физическое сохранение**: код сохраняется в каноническом синтаксисе с директивой `language: <код>;`.

### 3.2. `AiHardwareSandbox` (Аппаратная песочница)
* Реализует `HostSPI` с эмуляцией шин I2C, SPI, UART и протокола Modbus TCP/RTU.
* Включает встроенные профили типовых компонентов:
  * **Bosch BME280** (`0x76`): регистр идентификации `0xD0 -> 0x60`, калибровочные регистры и эмуляция температуры/давления/влажности.
  * **Modbus PLC Gateway** (`127.0.0.1:502`): регистры котла (100 = 245 -> 24.5°C), насоса (101 = 1) и клапанов.
* Проверяет границы прав доступа через `CapabilityScope` перед выполнением транзакции.

### 3.3. `StudioAiDiagnostics` (Машиночитаемый AI-интерфейс)
* Генерирует отчеты в формате JSON для интеграции с LLM и автономными кодогенераторами:
  * Метаданные доступных шин и периферии (`probe`).
  * Структурированные ошибки синтаксиса и безопасности (`PERMISSION_DENIED`, `SCOPE_VIOLATION`, `STEP_LIMIT_EXCEEDED`).

## 4. Дорожная карта графического интерфейса (GUI Roadmap)

1. **Этап 1 (Текущий, v1.1.0)**:
   * Ядро `:common-editor` полностью стабилизировано и протестировано.
   * Консольный движок `:desktopApp` с автоматическим распознаванием адаптеров и запуском скриптов.
   * Базовая сборка модуля `:androidApp` с подключением к `:common-editor`.

2. **Этап 2 (GUI v1.2.0)**:
   * Интеграция **Compose Multiplatform** (Jetpack Compose для Desktop и Android).
   * Единая кодовая база UI:
     * Текстовый редактор с подсветкой синтаксиса на родном языке.
     * Панель аппаратных устройств (I2C/SPI Tree).
     * Живой осциллограф/монитор регистров Modbus в реальном времени.

3. **Этап 3 (Hardware Integration v1.3.0)**:
   * Десктоп: jSerialComm / LibFTDI для прямых аппаратных адаптеров FTDI FT232H, CP2102, CH340.
   * Мобильные устройства: Android USB Host API для работы с преобразователями USB-UART через OTG, Android BLE Central для беспроводных датчиков.
